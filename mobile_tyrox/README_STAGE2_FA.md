# TYROX Mobile — مرحله ۲: مشاهده زنده صفحه

این مرحله کلاینت اندرویدی Kotlin را به پروژه اضافه می‌کند و قابلیت **درخواست مشاهده زنده صفحه کامپیوتر** را از طریق WebRTC پیاده‌سازی می‌کند.

## قابلیت‌های این مرحله
- حفظ اتصال HTTPS با بررسی دقیق SHA-256 گواهی و توکن جفت‌سازی.
- فهرست‌کردن فایل‌ها و انتقال فایل با Android Storage Access Framework.
- ارسال درخواست WebRTC به `POST /api/stream/offer`.
- فقط دریافت ویدئو؛ ترنس‌سیور با حالت `RECV_ONLY` ساخته می‌شود و DataChannel ورودی بسته می‌شود.
- مشاهده صفحه تنها در صورتی فعال می‌شود که کامپیوتر مقصد در تنظیمات خود درخواست‌های مشاهده صفحه را مجاز کرده باشد.
- درخواست روی کامپیوتر مقصد باید توسط صاحب آن به‌صورت دستی تأیید شود؛ رد درخواست، timeout شصت‌ثانیه‌ای و توقف از سمت گوشی پشتیبانی می‌شود.

## ساخت APK
1. Android Studio یا Android SDK + JDK 17 و Gradle را نصب کنید.
2. پوشه `mobile_tyrox` را در Android Studio با گزینه **Open** باز کنید.
3. صبر کنید Gradle Sync تمام شود و وابستگی `org.webrtc:google-webrtc:1.0.32006` دریافت شود.
4. از مسیر **Build → Build Bundle(s) / APK(s) → Build APK(s)** خروجی بگیرید.

خط فرمان (پس از نصب SDK و داشتن Gradle):

```bash
gradle assembleDebug
```

خروجی معمولاً در این مسیر ساخته می‌شود:

```text
app/build/outputs/apk/debug/app-debug.apk
```

## راه‌اندازی مشاهده زنده
1. نسخه دسکتاپ TYROX را اجرا کنید و هر دو دستگاه را به یک شبکه محلی وصل کنید.
2. روی کامپیوتر مقصد، قابلیت درخواست مشاهده صفحه را فعال کنید.
3. در گوشی، IP، توکن جفت‌سازی و fingerprint گواهی را وارد و اتصال را برقرار کنید.
4. دکمه **Request live screen view** را بزنید.
5. صاحب کامپیوتر باید پنجره درخواست را ببیند و **Accept** را بزند. بدون تأیید، تصویر ارسال نمی‌شود.
6. برای پایان نشست، از گوشی **Stop live view** یا از کامپیوتر **Stop sharing** را بزنید.

## محدودیت‌های فعلی
- این نسخه فقط مشاهده زنده ویدئو است؛ کنترل موس/کیبورد، مدیریت پردازش‌ها و فرمان‌های سیستم هنوز پیاده‌سازی نشده‌اند.
- اتصال WebRTC فعلی برای شبکه محلی و بدون STUN/TURN تنظیم شده است. عبور از NAT یا شبکه‌های جداگانه پشتیبانی نمی‌شود.
- کد به‌صورت ایستا بررسی شده، اما در این محیط APK ساخته نشده و روی گوشی واقعی تست نشده است. قبل از استفاده عملی باید Gradle Sync، build و تست دو دستگاه انجام شود.
- کلاس‌های API کتابخانه WebRTC ممکن است بسته به نسخه وابستگی نیازمند اصلاح جزئی باشند؛ خطاهای کامپایل واقعی باید بعد از Gradle Sync بررسی شوند.

## امنیت
- نشست فقط پس از تأیید صریح صاحب کامپیوتر آغاز می‌شود.
- گوشی فقط ویدئو دریافت می‌کند و هیچ مسیر کنترل ورودی در این مرحله وجود ندارد.
- TLS با fingerprint از پیش ارائه‌شده pin می‌شود؛ خطای تطبیق گواهی باید اتصال را متوقف کند.
